# 隧道通风按需调控系统

依据**实时车流**与**污染物浓度**，在 10 分钟级尺度上动态调节射流风机组合，
在**能耗**与**行车安全（卫生限值）**之间寻优。

零运行时依赖（仅用 Node.js 内置模块），开箱即用。

---

## 它做什么

传统隧道通风多为「定时段固定档位」或「75% 风机常开」，在夜间/自由流时段浪费大量电耗。
本系统按"需要多少风，开多少机"运行：

```
车流检测（流量/车速/货车比例）
        │
        ▼
交通预测（1800s 滚动时域，均值回归模型）
        │
        ▼
逐档位浓度推演（全混合瞬态模型 + 末端稳态约束）
        │              ┌── 0~8 组中选「最不利污染物占限值比 ≤ 88%」的最小组数
        ▼              ▼
   能耗最优档位 ◄──── 目标 = 最小组数
        │
        ▼
滞环 + 最小停留时间（加机 60s / 减机 180s，减机一次只减一组）
        │
        ▼
执行（磨损均衡：加机选最闲组、减机停最忙组）
        │
        ▼
实测越限保护（立即加机，无视停留时间）→ 开满仍超标则紧急报警
```

**人工不可旁路安全**：人工/停机模式下若实测越限，安全联锁自动接管，
且联锁带滞环闩锁——必须同时满足「浓度降到 70% 以下」**和**「预测车流已消散」才交还人工，
避免"全关→浓度重新积累→长期超标"的振荡。

## 快速开始

要求 Node.js ≥ 18。

```bash
npm start                 # 启动，默认 http://localhost:8088
PORT=8099 npm start       # 自定义端口
```

打开浏览器即可看到监控大屏，无需构建步骤。

控制：
- **仿真倍速**：暂停 / 30× / 60× / 300× / 600× / 1800×（真实 1 秒 = 仿真分钟数）
- **车流工况**：跟随 24 小时曲线，或锁定 夜间 / 自由流 / 高峰 / 拥堵 / 事故缓行
- **控制模式**：自动按需 / 人工（勾选风机组）/ 最大通风 / 停机
- **演练**：🔥 火灾演练（全部风机联锁投入排烟）、货车 ×2 压力（开满仍越限→报警）、复位

## 24 小时仿真结果（种子 7）

| 指标 | 按需调控 | 基线（75% 风机常开） |
| --- | --- | --- |
| 全天电耗 | **506.5 kWh** | 4320 kWh |
| 节能率 | **88.3%** | — |
| 越限次数 | **0**（安全率 100%） | 0 |
| 最不利污染物峰值占限值 | **82%** | — |
| 风机运行时间 | 17%（83% 时间全停） | 100% |

磨损均衡：8 组风机全天累计运行 0.90 ~ 2.92 h，无长期偏用某组。

典型工况稳态标定（最不利污染物占限值 %，行=开启组数；`npm run calibrate` 可复现）：

| 工况 | 活塞风 | 0 组 | 2 组 | 4 组 | 8 组 |
| --- | --- | --- | --- | --- | --- |
| 夜间（250 辆/h，78 km/h） | 98 | 16% | 15% | 14% | 13% |
| 自由流（1600，65） | 99 | 29% | 23% | 20% | 17% |
| 事故缓行（1800，12，货车多） | 53 | **159%** | 109% | 83% | 58% |
| 拥堵（3300，8） | 64 | **225%** | 163% | 128% | 92% |
| 拥堵 + 货车排放 ×2 | 64 | 368% | 266% | 209% | **149% → 报警** |

分层明确：**夜间/自由流靠活塞风（免费）零开机；高峰开 1~5 组；拥堵开满；
设备能力不足时报警而不是假装安全。**

## 物理模型（`src/physics.js`）

全混合（well-mixed）近似，统一用与限值同量纲的"负载单位"计算：

- **稳态**：`C = C₀（本底）+ E / Q`
- **瞬态解析解**：`C(t) = C∞ + (C(0)−C∞(0))·e^(−Q/V·t)`
  隧道体积 `V = 3200m × 68m² ≈ 2.18×10⁵ m³`，换气时间常数 30~60 分钟——
  这正是控制器不能只看当前浓度、而必须做长时域预测 + 末端稳态约束的原因。
- **排放源**：`E = 流量 × 隧道长 × 车队排放因子`；排放因子随车速降低升高；
  CO/NO₂ 用 ppm 换算（CO 1 ppm = 1.145 mg/m³，NO₂ 1 ppm = 1.88 mg/m³），
  烟雾以消光系数 k(1/km) 计（PM × 质量消光系数）。
- **活塞风**：`25 + 0.9v + 35·V/C`（m³/s），车速主导——
  自由流时 100 m³/s 左右的"免费风"，拥堵时骤降到 50~65 m³/s。
- **射流风机**：8 组 × 2 台 × 15 kW，单组名义诱导风量 12.5 m³/s，
  多组并列按组次线性折减（组间气流干扰）。

卫生限值（可在 `src/config.js` 按实际规范调整）：
正常 CO 100 ppm / NO₂ 5 ppm / k 7.5；阻塞短时 CO 150 ppm / NO₂ 5 ppm / k 9。

## 控制器（`src/controller.js`）

- **滚动预测寻优**：对 0~8 组逐档推演 1800s 时域，取全时域（含末端稳态）满足
  目标占限比 0.88 的最小组数。
- **滞环与停留**：加机最小停留 60s、减机 180s；减机一次只减一组。
- **实测保护**：实测 ≥100% 立即加机（无视停留）；≥95% 允许提前加机；<70% 才允许减机。
- **紧急报警**：全部风机运行仍越限 `ALL_FANS_INSUFFICIENT`；
  预测显示开满仍严重超标 `FORECAST_OVERLOAD`。
- **火灾联锁**：全部风机投入排烟。
- **磨损均衡**：按累计运行时长选组。

```

├─ src/

```

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全量状态快照（浓度、车流、风机组、计量、事件、趋势） |
| GET | `/api/events` | SSE，250ms 推送一帧状态 |
| POST | `/api/control` | `{action:'mode',mode,groups?}` / `fire` / `fire-clear` / `truck-factor` |
| POST | `/api/sim` | `{speed}` / `{reset}` / `{regime}` |

## 接入真实系统的替换点

当前为仿真闭环；接入工程现场只需替换两处，控制器与界面不变：

1. `Simulator.tick` 中交通/浓度的推进 → 改为现场 SCADA/检测器读数（CO/VI 仪、
   微波车检器、气象站）；
2. `decide()` 输出的 `nextGroups` → 下发到风机控制柜/PLC（建议保留"远程/就地"
   硬接线切换与联锁优先级）。

物理参数全部集中在 `src/config.js`，按实际隧道长度、断面积、风机铭牌、当地规范
限值标定即可。
