# 隧道通风按需调控系统

依据**实时车流**与**污染物浓度**动态调节射流风机组合，在行车安全（CO、烟雾能见度）与风机电耗之间取得平衡的仿真与可视化系统。

零运行时依赖（仅用 Node.js 标准库），零构建步骤。

```bash
node src/server.js        # 启动，默认 http://localhost:8080（PORT 可改）
npm test                  # 19 个自动化测试
```

---

## 它做什么

传统隧道通风按"高峰定时编组"常开风机——车流再小也全负荷运转。本系统改为**按需调控**：

> 车流低、浓度低 → 风机停转，只靠自然风 + 交通活塞风；
> 车流涨、浓度逼近控制目标 → 前馈提前开机 + 反馈加机；
> 火灾或污染物超应急限 → 安全越权，所有健康风机无条件立即投入。

五种 24 小时交通场景的仿真结果（相对"常开 12 台"定时编组）：

| 场景 | 定时编组电耗 | 按需调控电耗 | 节能 | 按需是否超限 |
| --- | ---: | ---: | ---: | --- |
| 典型工作日（双峰+事故拥堵） | 6337 kWh | ~520 kWh | **~92%** | 否 |
| 夜间低交通 | 6337 kWh | 0 kWh | **100%** | 否 |
| 节假日大流量 | 6337 kWh | ~370 kWh | **~94%** | 否 |
| 重载货车上坡段（柴油 60%） | 6337 kWh | ~1340 kWh | **~79%** | 否 |
| 火灾应急演练 | 6398 kWh | ~300 kWh* | **~95%** | 火灾窗口期内不可避免 |

\* 火灾发生时全部 16 台立即投入排烟，火源解除、污染物降回限值以下后自动回落。

## 控制策略（三层）

```
        ┌─────────────────────────────────────────────┐
        │ 1. 安全越权（最高优先级，无滞回无台数限制）      │
        │    火灾 / CO > 150 ppm / k > 0.012 m⁻¹        │
        │    → 全部健康风机立即投入                       │
        └─────────────────────────────────────────────┘
                          ↑ 不满足时
        ┌─────────────────────────────────────────────┐
        │ 2. 前馈（车流 → 排放 → 需风量）                │
        │    Q_req = max(E_CO / C_CO*, E_k / C_k*,      │
        │               Q_min) − Q_自然 − Q_活塞         │
        │    折算所需风机台数，提前于浓度恶化动作          │
        └─────────────────────────────────────────────┘
        ┌─────────────────────────────────────────────┐
        │ 3. 反馈（PI，以实测浓度修正前馈倍数）           │
        │    浓度/目标 > 1 → 增机（立即确认，超 1.15 加倍）│
        │    浓度/目标 < 0.7 且持续 60 s → 减机          │
        └─────────────────────────────────────────────┘
```

**抗抖动与设备保护：**

- 宽滞回带（增机线 ×1.1、减机线 ×0.7）+ 非对称确认周期（增 10 s / 减 60 s），抑制浓度在目标附近时的频繁启停；
- 单台最小连续运行 120 s、停机后重启冷却 60 s、单次决策最多增减 4 台（避免电网冲击）；
- 射流风机风量一阶爬坡（τ=35 s），控制律把这段滞后算进提前量；
- 增机优先选累计运行最短的、减机优先停累计最长的，多日运行下磨损自然均衡；
- 故障风机自动剔除并告警；人工模式下应急仍可越权（安全永远高于人工设定）。

三种运行策略可在大屏切换：**按需调控 auto / 定时编组 fixed / 人工单机 manual**。

## 物理模型

一维均匀混合（CSTR）近似：

```
V · dC/dt = E(t) − Q(t) · C
```

- **E（源项）**：交通量 × 单车排放因子（CO、烟雾分车型），低速拥堵按指数曲线恶化（15 km/h 时约 ×3~4）；火灾按独立源项叠加；
- **Q（通风量）** = 洞口自然风 + 交通活塞风 `v_p = k·Q交通·(v/v₀)^0.5` + 射流风机诱导风（含爬坡）；
- 烟雾用消光系数 k（m⁻¹）表示，按 能见度 ≈ 2.63/k 换算；
- 限值参照公路隧道通风设计思路取演示值：正常 CO 100 ppm / 阻滞 150 ppm，正常 k 0.0065 / 阻滞 0.009，控制目标取限值的 70%。

> 这是控制策略验证用的集总参数模型；真实长隧道应替换为沿纵向分段的一维对流-扩散方程，并接入实测 CO/VI 数据标定排放因子。所有参数集中在 `src/config.js`。

## 实时大屏

`http://localhost:8080/`（SSE 推送，无轮询）：

- 隧道纵剖面：车流密度、烟雾着色、风向箭头（长度∝风量）、16 台风机实时旋转状态；
- 9 项 KPI：时刻、车流、车速、CO、能见度（带限值进度条）、总风量、运行台数、累计电耗、超标占比；
- 三条历史曲线：交通流 / 污染物（带限值线）/ 风量构成与台数；
- 调控器决策面板（前馈需风、反馈倍数、目标台数、拥堵判定）与事件流；
- **点击风机**：注入/解除故障（人工模式下为单机开关）；
- 60×–1800× 仿真倍速、单步推进、重置；「策略对比」按钮一键跑全部场景。

REST 接口：`/api/run` `/api/pause` `/api/step` `/api/reset` `/api/mode` `/api/fan` `/api/compare`，实时流 `/api/stream`。

## 文件结构

```
tunnel-ventilation/
├─ src/
│  ├─ config.js       隧道/风机/排放/限值/控制全部参数（唯一配置入口）
│  ├─ physics.js      排放因子、活塞风、CSTR 扩散积分、单位换算
│  ├─ scenarios.js    5 个 24h 交通场景（分段线性时间线 + 火灾窗口）
│  ├─ controller.js   FanController：三层决策、滞回、设备保护、磨损均衡
│  ├─ simulator.js    时间步进仿真 + 能耗/安全指标 + 策略对比
│  └─ server.js       HTTP + SSE + 静态托管（零依赖）
├─ public/            实时大屏（原生 JS + Canvas，无框架无构建）
└─ test/              node:test：物理 6 项 + 闭环/安全/保护/均衡 13 项
```

## 接真实系统时的替换点

1. `simulator.js` 的交通/浓度输入 → 现场线圈/雷达车检器 + CO/VI 传感器（SSE 上行链路可直接复用）；
2. `physics.js` 排放因子 → 用本隧道实测与当地车队结构标定；
3. `controller.js` 的台数输出 → PLC/环网控制器（增机/减机指令、状态回采、故障字一一对应）；
4. 长隧道改为纵向分段模型时，每段各跑一个 FanController 实例即可，决策接口不变。
